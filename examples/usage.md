# 使用示例

先加载[完整版](../prompts/full.md)或[精简版](../prompts/lite.md)，再发送任务。以下均为**虚构演示或占位模板，不是实际业务事实、正式反馈或现行政策原文**。不要将示例数字、单位、结论或程序复制进真实材料充当依据。

## 示例一：只改错字，不反复追问

```text
以下为虚构演示。只改错字和标点，不调整事实或结构。
原文：截至目前，相关工作已按计划布署。请有关人员核对帐号信息。
只返回修改后句子和一句修改说明。
```

预期：按普通C类处理，将“布署、帐号”改为“部署、账号”，不追问签发人，不把“已”改为“拟”，不输出全套高风险审查栏目。

## 示例二：涉资金请示，不编造金额和依据

```text
任务：起草一份项目经费请示，约800字。
签发主体：【待补：单位与层级】
主送：【待补：有隶属关系的上级机关】
目的：申请批准【待补：项目及经费事项】。
项目事实：【待补：必要性、现有条件、工作内容】
金额、测算明细及来源：【待补】
内部研究、预算安排及其他已履行程序：【待补：据实填写】
拟完成时间及依据：【待补】
请先指出会影响文种或权限判断的缺项；其余用待补形成可用草稿。
不编造预算文件、会议日期、金额、文号或同意意见。
```

预期：A类；确认最少定位；保留必要背景、理由和依据，单列请求事项；程序不足不能写“经研究同意”。不能为凑800字生成虚假事实。

## 示例三：整改报告锁定反馈原文

```text
以下为虚构测试，不对应真实巡视或审计事项。
任务：给上级主管部门起草整改情况报告。
主体：某单位；对象：上级主管部门；目的：报告整改进度。
演示反馈原句：“采购审批程序执行不到位。”
该句在本测试中视为已经确认、允许引用的原文，不得改动。
事实：共3项整改任务，其中2项已完成并验收，1项仍在推进。
责任主体和期限：【待补】
请如实区分完成与未完成，不将问题改成一般沟通不足，不写全部整改到位。
```

预期：A类；反馈原文保留，进度相符；缺失责任和期限待补；不能因“对主管部门报告”就自动降低正式问题性质。

## 示例四：国企未经审计实际数

```text
以下为虚构测试数据，不能用于实际披露。
任务：核查一份国企内部经营简报，只列关键问题和建议。
主体：某公司；对象：有权阅知的内部经营班子；不对外发布。
素材：财务已确认的某期营收为1200万元，属于未经审计的实际数；
上年同期营收为1000万元，统计范围和会计口径一致。
原稿写为“经审计实现营收1200万元，预计同比增长20%”。
请校准审计状态和实际／预计状态，不改原始金额，不编造审计机构。
```

预期：识别“经审计”与材料冲突；实际数不能改成预计数；基于已给数据计算同比20%可复核。明确当前场景的使用范围，不误认为“内部”就可以上传任何受限原件。

## 示例五：真实完成，不机械降成基本完成

```text
以下为虚构验收测试。
任务：润色内部整改进展，主体与对象沿用本测试已明确口径。
事实：截至测试所设统计日，任务清单10项均已完成并验收；
验收口径、时间、范围均已确认。
原句：“清单内10项任务已全部完成，完成率为100%。”
请保留事实强度，不额外保证今后零问题。
```

预期：因整改内容执行A类，但“全部、100%”属于测试中已确认事实，应保留；不得改为“基本完成”“力争完成”，也不增加永久零风险保证。

## 示例六：只改指定部分

```text
这是同一对话的下一轮修改。
当前版本：v1.0初稿。
第一、二部分及已确认事实、数字、反馈原文不动。
只重写第三部分“下一步措施”，让每条有主体、任务、节点和验收方式。
原第三部分：【待补：可使用的原文】
已有责任与时限：【待补：已经确认的分工和节点】
未确定的机制可以列建议项，不写成已经研究决定。
只输出修改后的第三部分及关键变更点，版本标v1.1局部修订。
```

预期：只处理指定范围。若第三部分与前文事实冲突，先列联动需求，不静默重写全文。新会话应附[交接包](../templates/revision-log.md)，不能假设模型记得历史对话。

## 示例七：数据核查，先指出问题

```text
以下都是虚构算术测试数据。
只核数据逻辑，不写公文全文：
1. 合格率从85%提高到90%，稿件写“提高5%”。
2. 年度计划100项，完成120项，稿件写“超额完成120%”。
3. 三个互斥且穷尽的构成比例分别为30%、40%、40%。
请指出问题；如无法判定哪个原始数据错，列待核，不擅自改原数。
```

预期：分别指出“提高5个百分点”“完成计划120%或超额完成20%”、合计110%需要核原始数据。不能自行把第三个40%改成30%来凑100%。

## 正文区与提示区示意

下面只示意输出分区，**不是可直接报送的正式通知**。代码块是本说明文件用于展示纯文本的容器，不要求助手在公文正文外加代码围栏。

```text
版本：v1.0｜结构示意，待补
【正文】
关于【待补：事项】的通知

【待补：主送单位】：
为【待补：有依据的工作目的】，现就有关事项通知如下。
一、【待补：具体事项】
【待补：责任主体、任务和完成时限】。
二、【待补：工作要求】
【待补：执行标准、反馈方式和联系人角色】。
特此通知。

【待补：发文机关】
【待补：成文日期，不能默认用起草日期】

【参谋提示】
本文仅为结构示意，不能作为已完成审签的文件使用。
【待补信息】
需补主送、依据、事项、责任、期限及署名日期等实际信息。
```
