# 常用文种默认结构

## 请示

标题 → 主送机关 → 事由 → 依据 → 请求事项 → 结语。

一文一事；一个主送；不夹叙夹议过多；结语一般用“妥否，请批示。” 标题避免“关于请求支持 XX 的请示”，改为“关于 XX 的请示”。

## 报告

标题 → 基本情况 → 主要做法／成效 → 存在问题 → 原因分析（如需）→ 下一步工作 → 结尾。

只汇报不审批；避免“请予批准”“请予批复”。

## 方案

标题 → 指导思想 → 工作目标 → 主要任务 → 实施步骤 → 责任分工 → 保障措施。

目标可检验；任务能分解；措施能落地；责任能落实。

## 通知

标题 → 通知事项 → 任务要求 → 时间安排 → 有关说明。

内容清晰，执行导向明确，避免写成讲话稿。

## 函

标题 → 来由 → 事项 → 协商内容 → 结语。

平行语气，协商口吻，不用命令式。

## 纪要

会议基本情况 → 议题讨论情况 → 议定事项 → 需落实事项 → 有关要求。

不写流水账；不杜撰一致意见；不把讨论意见写成最终决定。能写“原则同意”的，不写成“完全确定”。

## 通报

标题 → 基本情况（事实）→ 主要做法／问题 → 要求或部署。

区分表扬、批评、情况三类；批评定性与本级权限匹配。

## 整改／剖析／对照检查

存在问题 → 原因分析 → 整改措施 → 责任分工 → 完成时限。

问题要实；原因要准；措施要对应；时限可落地；不写空泛忏悔，不写自毁式定性。

## 汇报材料

总体情况 → 主要做法 → 工作成效 → 存在问题 → 下一步打算。

有情况、有数据、有例子更好；没数据标【待补】。

## 讲话材料

开场定调 → 讲成绩 → 讲问题 → 讲要求 → 讲落实。

有现场感、有层次；不能过于书面化，也不能过于口语化。

## 情况说明／说明材料

背景说明 → 事实经过 → 处理情况 → 目前状态 → 风险提示／后续建议。

以澄清和解释为主；不轻易下结论；不扩展到无关问题。
